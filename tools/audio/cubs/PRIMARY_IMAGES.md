# Cubs live-baseline primary images

`build-primary-images.sh` builds real vendor and system_ext EROFS payloads. It
does not flash, start a device service, run Soong, or calculate hashes. Finish
the actual Cubs component build and `compile-primary-policy.sh` first; do not
run while their inputs or the canonical integration are being edited.
The source-staging helper must make modified copied sources newer than existing
objects: preserving an older canonical mtime can otherwise make Ninja retain an
old helper. The real Cubs rebuild must finish before selecting its product out.

From the repository root:

```sh
integration=work/audio-research/cubs/primary-hal-integration-20260923
tools/audio/cubs/build-primary-images.sh \
  --live-root "$integration" \
  --product-out work/aosp/out_pixel/cubs/target/product/cubs \
  --policy-dir "$integration/policy-v2" \
  --output-dir "$integration/images-NEW"
```

The output directory must not already exist. Required host packages are
`python3`, `binutils` (`readelf`), `coreutils`, and passwordless `sudo` for the
workspace's ownership-preserving staging operation. Android's built Cubs
`mkfs.erofs` and `sefcontext_compile` are required; `--host-bin` can select their
directory. `--metadata-dir` selects the Cubs target-files `META` directory.

Inputs are the captured `baseline/vendor.img`, `baseline/system_ext.img`,
`vendor-root`, `system_ext-root`, and `live-policy/{system,product}` underneath
`--live-root`. The extracted roots must preserve UID/GID/mode (root extraction
with `fsck.erofs --extract=... --no-xattrs` on this WSL filesystem). They are
never modified. Output `staging/` retains those owners and modes; only new owned
files use explicit Android ownership. Existing inode metadata takes precedence
over potentially older target-files metadata. The latter supplies capability
bits only, and a nonzero capability entry must match the preserved inode.
Current captured-target META has no nonzero capabilities in these partitions.

The overlay is limited to the Cubs-role HAL, boot helper, canonical RC/VINTF,
the Bluetooth-audio reference fragment, completed policy,
`ro.audio.flinger_standbytime_ms=0`, and the recursive ELF
dependency closure available in that same completed product output. Vendor and
system_ext dependency libraries are copied; platform/product/APEX libraries are
recorded as prerequisites of the retained OS, never relocated into vendor.
Their on-device ABI compatibility still requires the actual boot. No dependency
module's RC or VINTF declaration is installed implicitly.

The Bluetooth-audio fragment is stored at
`/vendor/etc/powerphone-cubs-bluetooth-research.prop`. The **active** overrides
are the corresponding platform `early-init` commands in the installed
system_ext gate RC: appending false values to vendor/build.prop alone would
lose to the retained donor product properties. Only the unsupported audio
profiles are disabled; BLE/GATT/HID are untouched.

The proprietary primary RC and audio/BT VINTF fragments are moved out of the
image into `removed-from-image/`; the originals remain in the captured roots.
SELinux xattrs are regenerated by mkfs using the captured platform, product,
system_ext, optional ODM, and **new merged vendor** file contexts. Merely copying
the context text into vendor would not label the image correctly.

Successful output includes `COMPLETE`, `vendor.img`, `system_ext.img`, build
logs, source locations, copied/external dependency records, exact per-inode
filesystem configurations, and merged contexts. Raw EROFS payload sizes must
not exceed their corresponding captured images unless the operator supplies
an explicit `--max-vendor-bytes` or `--max-system-ext-bytes` ceiling. A larger
image is reported as requiring logical-partition growth; the operator must
verify super capacity and handle that resize at flashing time. No AVB footer is added; AVB
configuration, flashing, first boot and API/acoustic qualification remain
separate operations. Failed output is retained without `COMPLETE` for diagnosis.

`--allow-frankel-build-output` is an explicit transitional cross-build option,
not the normal Cubs recipe. Even then the named binaries must be the Cubs-role
HAL and Cubs boot helper; this does not change or repack any Frankel image.
